# P0：后台数据监控与估值快照

实现日期：2026-09-07。状态：本地实现；VPS 部署与真实交易时段验收尚未执行。

## 运行方式

复用 `agent-foundry-backend` systemd 服务，在 Rust 进程中启动后台监控任务。没有新增常驻进程。现有结构化产品抓取仍通过临时 Python 子进程执行。

- `PORTFOLIO_MONITOR_ENABLED=true`：默认启用。
- `PORTFOLIO_MONITOR_INTERVAL_SECONDS=300`：标的行情请求间隔，支持 60–3600 秒。
- `PORTFOLIO_MONITOR_RETENTION_DAYS=30`：小时快照保留天数，支持 7–3650 天；下限保证 168 小时历史接口完整。
- 后台每轮完成后等待最多 60 秒检查数据状态；上传持仓或人工刷新产品可唤醒检查。检查时间会包括网络与数据库耗时，不是严格每分钟。
- 扫描所有现有持仓，按共享的 ISIN、公司名与明确标的代码识别 Alpaca 标的，去重、排序并按现有请求上限分批。没有映射的持仓仍保留在分母和明细内。
- 标的代码注册表位于 `web/src/utils/marketSymbols.json`，由前端和 Rust 编译期共用。名称识别规则保守，未识别的代码不自动猜测。跨市场股票、ADR 等映射可能仅是代理，未将其用于自动改写股票的账户估值。

## 交易时段与故障处理

美股使用现有 Alpaca 客户端的只读 `/v2/calendar`，每日读取前后两周的日期与开收盘时间，支持节假日与提前收盘。纽约时间转 UTC 使用 2007 年以后的美国夏令时规则，与柏林时区分开。

交易时段按配置频率更新；收盘后、启动或标的集合变化时可补取一次。正常休市后不会持续刷新同一份收盘报价。日历读取失败时每 15 分钟重试，最多接受前一日取得的日历；无法判定日历时明确标记未知，并允许按间隔尝试行情。

官方接口说明：[Alpaca Calendar](https://docs.alpaca.markets/us/reference/legacycalendar)。该接口若因账户权限或服务错误不可用，会显示日历未知，不用德国交易日替代美国交易日。

人工和后台 Alpaca 请求共用同一个互斥锁与缓存检查。单次刷新超时 45 秒，网络失败后共用 5 分钟冷却；监控轮次发生错误或缺失时等待至少 15 分钟。部分标的无报价不会触发整个服务的全局冷却，以免阻止后续批次。

结构化产品保留原约每小时的 Tier 1 刷新与收盘快照，仍使用现有 XETRA 日历和柏林 08:00–22:00 窗口。成功后至少间隔 60 秒再处理已排队请求；失败后至少间隔 5 分钟，等待期间合并请求。子进程最长执行 30 分钟，超时终止并显示错误；日历 HTTP 请求限制为 10 秒。

这里的产品刷新窗口是抓取策略，不能当作每份产品的障碍观察时段。按发行人条款精确计算日内障碍风险属于后续模型工作。

## 估值与数据质量

持仓汇总新增 `valuationSource`、`valuationCurrency`、`priceAsOf`、`priceFetchedAt`。保留现有的报价/PDF优先级与债券 PDF 市值规则，仅接受明确 EUR 的正数 Frankfurt 报价作为欧元估值覆盖。未知或其他币种沿用汇总的后备估值，并在监控中提示。

Frankfurt 当前抓取链路没有解析可靠市场时间，因此 `priceAsOf` 保持未知；原 `quote_timestamp` 仅用作 `priceFetchedAt`。PDF 上传时间也是导入时间，不能代表该 PDF 中报价的市场时间。交易价格后备值也不冒充当前市场行情。

Alpaca 的 `priceAsOf` 保留提供方报价时间，新增 `fetchedAt` 保留原数据库抓取时间。读取缓存或刷新失败不会重新打上当前抓取时间。

标的行情质量分为有效、休市且来自最近交易时段、过期、未知时间、未知日历、未来时间、缺失、未映射和无效价格。交易时段允许 10 分钟报价年龄；开盘最初 10 分钟允许最近收盘报价；休市参考最近收盘前 15 分钟。IEX 仅为单市场报价，稀疏报价会被标记过期，而不会被当成完整市场实时数据。

产品抓取与标的市场时间相差超过 24 小时会显示时间差提示。产品抓取窗口内，使用 Frankfurt 估值的仓位超过 120 分钟未抓取会显示抓取过期；这项检查不证明产品市场报价新鲜。

Greeks 暂无可验证的独立市场时间，因此明确显示未知，现有 Python enrichment 缓存/刷新规则继续适用。未新增或伪造 Greek 时间戳。

监控分母为全部持仓的市值；覆盖率使用绝对市值以避免多空抵消。现金、负债和完整账户 NAV 返回 `null`。界面的“总资产”卡改称“持仓市值”，压力测试分母同步注明。现有损益数字不变，快照不是现金流调整后的收益率或回撤。

有效标的行情覆盖率不等于衍生品模型覆盖率。缺失数据和非 Tier 1 持仓不会从监控消失。前端压力测试沿用后端选定的产品估值与实际持仓数量，避免旧 enrichment 覆盖新 PDF 或已变更数量。

## 快照、接口与界面

SQLite 新增 `portfolio_monitor_snapshots`，每轮在一个事务内更新 `latest` 和 `hour:YYYY-MM-DDTHH`。同一 UTC 小时保留最后一次观察；跨小时保留历史，每轮写入时在同一事务内删除早于保留期的小时快照，`latest` 不受影响。它不是每个 tick 的不可变历史。每份快照含完整输入，约 0.5 MB，默认 30 天保留时容量稳定在约 350 MB；删除释放的页由 SQLite 复用，数据库文件不会自动缩小。

快照包含全持仓估值、enrichment、实际读取的标的报价、数据质量、日历判断、提供方状态，以及全部持仓产品报价下跌 20%/50%/100% 的直接压力结果。保存输入便于追溯，但没有声称多个来源在同一市场时点原子更新。

接口：

- `GET /api/portfolio-monitor/status`：运行状态和最新快照，不重复传完整原始输入。
- `GET /api/portfolio-monitor/history`：最近 168 份小时快照的键和时间。
- `GET /api/portfolio-monitor/snapshots/{key}`：读取完整快照及输入，键不存在返回 `null`。

压力测试面板新增后台数据监控区域，前端每 30 秒读取状态，展示覆盖率、过期与未知信息。可展开全部持仓的来源和时间。最近检查超过 3 分钟、监控关闭或运行失败时，提示快照不能代表当前状态；失败不清空上一次有效快照。

## 验证与剩余边界

本地验证覆盖美股节假日、提前收盘、美国/欧洲夏令时差异、旧报价与未知时间、全持仓分母、未知现金、估值来源优先级、币种过滤及 SQLite 重开后的快照保存。前端测试检查新 PDF 估值与数量不被旧 enrichment 覆盖。

P0 提供持续数据检查和直接报价压力快照。完整衍生品情景引擎仍由前端运行；个性化限额、预警生命周期、消息推送及减仓决策比较属于 P1/P2，尚未实现。Greeks 市场时间未知、现金余额缺失和未映射标的在界面明确保留。

部署使用现有 `deploy/deploy-backend.sh`。部署后应关闭浏览器，观察交易时段内至少两次后台刷新，再检查休市行为、失败重试、最新快照及重启后的快照读取。此生产验收不由本地测试代替。
